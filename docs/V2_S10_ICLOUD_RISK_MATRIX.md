# ClipEase V2 Stage 10 iCloud 同步风险矩阵

任务卡：`V2-S10-ICLOUD-RISK-MATRIX-001`

阶段：Stage 10 iCloud 同步预研 - 风险矩阵

结论：PASS 产出风险矩阵；HOLD 任何正式同步、CloudKit runtime、entitlement、record schema、SQLite schema 迁移、同步 UI、附件上传下载、跨设备删除传播、冲突合并 runtime 和端到端加密 runtime。

## 1. 当前用户确认边界

- Stage 10 只做预研，不提供任何用户可见同步能力。
- CloudKit private database 是未来正式同步的首选候选方案。
- 端到端加密是未来正式同步的前置门槛；CloudKit private DB 不能被表述为 App 级 E2EE。
- 附件 / 图片 / 富文本附件同步暂缓。
- 删除同步暂缓，不做跨设备删除传播。
- 文件卡片只同步路径历史，不上传原文件；跨设备路径不可用时只能显示不可用 / 原设备路径语义。
- 设置同步只评估少量低风险设置，不同步隐私敏感配置。

## 2. 等级说明

- 概率：低 / 中 / 高，表示未来进入正式同步时发生该风险的可能性。
- 严重度：P0 / P1 / P2 / P3。P0 为可能造成敏感数据泄露、不可逆数据丢失或重大信任破坏；P1 为正式同步必须解决的高风险；P2 为需要设计和测试覆盖的中风险；P3 为可通过文案、限制或后续优化处理的低风险。
- 是否阻塞正式同步：是表示未完成缓解和测试前不得发布正式同步；条件阻塞表示可通过缩小首批范围绕开；否表示不阻塞但必须记录。

## 4. 阻塞汇总

正式同步发布前必须先解决或通过范围缩小绕开的阻塞项：

- 必须解决：S10-R01、S10-R02、S10-R03、S10-R04、S10-R05、S10-R06、S10-R08、S10-R10、S10-R11。
- 条件阻塞：S10-R07、S10-R09。若首批同步范围足够小，可以限制重复捕获、附件和全量历史规模，但仍需测试和文案覆盖。

## 5. Stage 10 后续只读产物衔接

- Schema gap 清单应从 S10-R03、S10-R04、S10-R05、S10-R07、S10-R08、S10-R10 反推所需字段和迁移边界。
- 同步数据字典应从 S10-R01、S10-R06、S10-R11 反推每类字段是否可同步、是否敏感、是否需 E2EE、是否可重建和是否需用户确认。
- 后续任何 CloudKit zone / record mapping、tombstone lifecycle、conflict fixture、attachment CKAsset、privacy consent 或 E2EE spike 都必须另开任务卡，并继续保持 Stage 10 红线，直到用户明确放行实现。
