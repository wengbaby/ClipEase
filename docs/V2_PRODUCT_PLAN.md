# 第二版产品方案

## 1. 版本定位

第二版目标是把轻贴 ClipEase 从“稳定好用的剪贴板历史工具”升级为“高性能、可管理、可长期保存的剪贴板工作台”。

第二版不追求一次性做完所有高级能力，优先解决长期使用会遇到的三个问题：

- 历史数量变多后的性能和稳定性。
- 常用内容需要长期保存、分类和再次使用。
- 搜索和管理能力需要比第一版更精确。

## 2. 已确认方向

用户已确认：

- 第二版优先以“性能和管理能力”为核心，不马上实现 iCloud 同步。
- “收藏”和“置顶”分开。
- 分组采用类似文件夹的管理方式。
- 置顶内容不受保存期限影响；取消置顶后，如果已经超过保存期限，下次清理时会按普通历史清理。
- 取消收藏后，内容直接变成普通历史，并按当前保存期限参与清理。
- 普通历史进入分组时，动作定义为“收藏到分组”，并自动成为收藏内容。
- 普通历史允许直接编辑；用户编辑提交后，保存为一条新的历史文本记录，不覆盖原记录。
- 多选通过右上角或更多菜单进入“管理模式”，不在日常浏览中默认触发。
- 第二版先做敏感 App 忽略和敏感内容遮罩，暂缓本地加密。

## 3. 核心概念

### 3.1 普通历史

普通历史是用户复制产生的临时记录。

规则：

- 继续按保存期限自动清理。
- 可以搜索、预览、复制、粘贴、删除。
- 可以置顶。
- 可以收藏到长期保存区域。
- 可以移动或复制到分组。

### 3.2 置顶

置顶是临时排序能力，不等于永久保存。

规则：

- 置顶内容显示在普通历史最左侧。
- 置顶内容不受普通保存期限清理。
- 用户可以取消置顶。
- 取消置顶后，如果该内容已经超过保存期限，下次清理时按普通历史清理。
- 置顶不自动进入收藏或分组。

### 3.3 收藏

收藏是长期保存能力。

规则：

- 收藏内容不受普通历史保存期限影响。
- 收藏有独立筛选入口。
- 收藏内容可以取消收藏。
- 收藏内容可以属于某个分组。
- 收藏内容默认保留原来源 App、复制时间、类型和预览信息。
- 取消收藏后，内容直接变成普通历史，并按当前保存期限参与清理。

建议：

- 收藏内容从普通历史复制出一份长期保存记录，或者在数据库中转为保留记录，必须保证普通历史清理不会影响收藏。

### 3.4 分组

分组是用户主动管理长期内容的方式，类似文件夹。

规则：

- 用户可以创建、重命名、删除分组。
- 一个内容默认只属于一个分组。
- 未分组收藏内容显示在“未分组”中。
- 删除分组时，不直接删除内容，先询问是移动到“未分组”还是一并删除。

建议：

- 第二版先做单层分组，不做多级文件夹，降低复杂度。
- 分组优先服务收藏内容。
- 普通历史不能以临时历史身份直接进入分组；用户对普通历史执行“收藏到分组”时，系统自动将它变成收藏内容并放入目标分组。

## 4. 第二版功能建议

### 4.1 SQLite 数据库

目标：

- 支持几千到几万条历史记录长期使用。
- 搜索和筛选更稳定。
- 后续同步、分组、收藏、批量操作有可靠数据基础。

用户价值：

- 长期使用不容易卡顿。
- 数据维护更清晰。
- 更容易做备份、迁移和恢复。

### 4.2 收藏和永久保存

目标：

- 把临时历史和长期保存内容区分开。
- 用户可以保存常用文案、链接、图片、颜色和富文本。

入口建议：

- 卡片右键菜单：收藏 / 取消收藏。
- 预览窗口工具栏：收藏按钮。
- 顶部筛选：收藏。
- 更多菜单或设置页：管理收藏。

### 4.3 分组管理

目标：

- 用户可以把长期保存内容放进不同分组。

示例分组：

- 常用文案
- 代码片段
- 设计素材
- 链接资料
- 客服回复

交互建议：

- 顶部筛选或更多菜单进入“分组”。
- 分组列表保持简洁，不占用第一版主窗口的核心空间。
- 卡片右键支持“收藏到分组”。

### 4.4 更强搜索

目标：

- 搜索不仅按内容，还能按来源、类型、时间、收藏状态和分组过滤。

建议能力：

- 按来源 App 搜索。
- 按内容类型筛选：文字、图片、链接、颜色、富文本。
- 按时间范围筛选：今天、最近 7 天、最近 30 天、自定义范围。
- 只搜收藏。
- 只搜某个分组。
- 搜索结果继续保持黄色背景高亮。

### 4.5 历史内容编辑

目标：

- 文本、富文本和收藏内容可以再次编辑。

规则：

- 普通历史允许直接编辑。
- 用户编辑提交后，生成一条新的历史文本记录。
- 原始历史记录不被覆盖，避免用户误改后找不回原内容。
- 收藏内容编辑后同样生成一条新的历史或收藏记录，具体归属以后续交互设计为准。

### 4.6 批量操作

目标：

- 支持大量历史管理。

建议能力：

- 多选删除。
- 多选收藏。
- 多选取消收藏。
- 多选移动到分组。
- 多选导出。

规则：

- 多选入口采用“管理模式”。
- 普通浏览模式保持轻量，避免误触。
- 管理模式中显示多选状态、已选数量和批量操作栏。

### 4.7 隐私和安全增强

目标：

- 降低敏感内容被误记录的风险。

建议能力：

- 默认建议忽略密码管理器。
- 增加敏感关键词或格式识别，例如验证码、银行卡、Token。
- 对敏感内容只显示遮罩，点击后再显示。
- 设置某些 App 只记录文字、不记录图片。

规则：

- 第二版先做敏感 App 忽略和敏感内容遮罩。
- 本地加密暂缓，等 SQLite、搜索、收藏和分组稳定后再评估。

### 4.8 链接卡片增强

目标：

- 链接卡片更接近真实网页预览。

建议能力：

- 获取网页标题。
- 获取网页图标。
- 获取网页描述。
- 失败时显示简洁占位。
- 支持复制标题、复制 URL、复制 Markdown。
- 支持 `Command + E` 编辑 URL 地址。
- 链接编辑窗口参考 Paste：顶部取消/保存，中间编辑 URL，底部显示当前 URL，并提供“在 默认浏览器 中打开”按钮。
- “在 Chrome 中打开”“在 Edge 中打开”等按钮文案需要按系统默认浏览器动态显示。

### 4.9 图片能力增强

目标：

- 图片不只是历史记录，也可以被长期管理。

建议能力：

- 收藏图片。
- 图片加入分组。
- 查看原图。
- 复制为图片。
- 复制为文件。
- 导出图片。

### 4.10 iCloud 同步预研

第二版先做技术预研和数据结构预留，不建议直接实现。

原因：

- 同步会引入冲突、隐私、加密和附件传输问题。
- 在 SQLite、收藏、分组稳定前直接做同步，会放大复杂度。

### 4.11 富文本卡片展示

目标：

- 如果内容是富文本，卡片预览区域应显示带格式的富文本，而不是退化成纯文本。

建议规则：

- 卡片中按照复制时的富文本格式显示，包括字体样式、字号、文字颜色、背景色等可安全渲染的格式。
- 卡片预览需要限制渲染复杂度，避免大量富文本卡片影响主窗口流畅度。
- 搜索命中仍需高亮，但不能破坏富文本原格式。

### 4.12 新历史后的窗口位置

规则：

- 如果有新的剪贴板历史产生，下次打开主窗口时回到第一条卡片。
- 如果没有新历史，主窗口保留用户上次横向浏览位置。

原因：

- 有新内容时，用户最可能想看最新记录。
- 无新内容时，保留位置更符合继续浏览历史的预期。

### 4.13 快捷键体系补全

目标：

- 右键菜单、系统菜单、主界面更多菜单中的常用功能统一显示快捷键。

已建议快捷键：

- `Command + ,`：打开设置。
- `Command + E`：编辑当前文本或链接卡片。
- `Command + T`：暂停 / 恢复轻贴记录。
- `Command + D`：收藏 / 取消收藏。
- `Command + M`：进入或退出管理模式。

待补充候选：

- 移动到分组。
- 导出当前选中内容。

### 4.14 窗口层级

规则：

- 主窗口调出时需要保持在最前。
- 预览窗口打开后，预览窗口必须在主窗口前方。
- 点击主窗口外部仍按当前规则关闭主窗口；需要特别处理设置、帮助、新建文本等轻贴自己的窗口。

### 4.15 新建文本入口

规则：

- 用户通过主窗口 `...` 菜单点击“新建文本”后，主窗口应隐藏。
- 新建文本窗口独立显示，不因主窗口隐藏而关闭。

### 4.16 全局提示层

目标：

- 所有操作提示从主窗口左侧迁移到统一的提示层。

样式规则：

- 位置：底部中间靠上一点。
- 层级：最高层，不被主窗口、预览窗口、设置页覆盖。
- 外观：无边框、圆角、浅色半透明背景。
- 内容：显示来源 App 图标和短提示，例如“Paste 暂停”“Chrome 已收藏”“已复制”。
- 动画：淡入淡出。
- 时长：约 1 秒后自动关闭。

建议：

- 提示层只用于短反馈，不承载需要用户选择的确认操作。
- 需要确认的危险操作仍使用系统确认弹窗或专用确认 UI。

## 5. 建议优先级

### 第二版第一阶段：数据和管理基础

- SQLite 数据库迁移。
- 收藏 / 取消收藏。
- 收藏筛选。
- 分组基础模型。
- 更强搜索的基础字段准备。

### 第二版第二阶段：管理体验

- 分组管理界面。
- 收藏到分组。
- 批量操作。
- 收藏内容编辑。
- 快捷键体系补全。
- 全局提示层。

### 第二版第三阶段：内容增强

- 链接卡片增强。
- 图片操作增强。
- 富文本卡片展示。
- 隐私忽略和敏感遮罩。

### 第二版第四阶段：同步预研

- iCloud 数据结构评估。
- 附件同步策略评估。
- 冲突解决策略评估。

## 6. 第二版暂不建议马上做

- iCloud 正式同步。
- 端到端加密。
- OCR 图片文字识别。
- 多级文件夹。
- 插件系统。
- 团队共享。

这些能力价值明确，但复杂度高，建议等第二版核心数据层和管理能力稳定后再推进。

## 7. 待用户继续确认的问题

- 链接编辑窗口是否只保存 URL，还是未来也要增加标题/备注字段。
- 分组入口放在顶部筛选、更多菜单，还是单独的管理窗口。
- 收藏内容在主窗口中是否始终排在普通历史前，还是只在“收藏”筛选里显示。
- 敏感内容遮罩是否默认开启。
- 是否需要为每个分组设置自定义颜色或图标。
