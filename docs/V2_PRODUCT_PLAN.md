# 第二版产品方案

## 当前状态

截至 2026-05-19，第二版大部分核心功能已经完成，当前进入功能收尾、回归测试和发布准备阶段。

已落地的用户可见方向包括：SQLite-only 数据基础、分组归类、主窗口搜索 / 筛选、文件卡片、富文本编辑、颜色与图标弹窗、全局提示框、App 图标统一和多项主窗口交互修复。

后续产品侧重点从“继续扩范围”转为“按用户真实反馈修 bug、稳定交互、补齐回归和准备发布”。

## 1. 版本定位

第二版目标是把轻贴 ClipEase 从“稳定好用的剪贴板历史工具”升级为“高性能、可归类、可长期使用的剪贴板工作台”。

第二版不追求一次性做完所有高级能力，优先解决长期使用会遇到的三个问题：

- 历史数量变多后的性能和稳定性。
- 常用内容需要通过分组长期归类和再次使用。
- 搜索、选择、右键菜单和定位体验需要比第一版更精确。

## 2. 已确认方向

用户已确认：

- 第二版优先以“性能、分组归类和主窗口体验”为核心，不马上实现 iCloud 同步。
- 删除收藏字段和收藏功能；旧收藏数据可以完全清空，不再迁移或兼容。
- 删除管理模式，包括批量移动、批量删除等后续所有管理模式范围。
- 原 JSON 数据代码和 JSON 到 SQLite 迁移代码可以删除；后续开发采用 SQLite-only。
- 分组采用类似文件夹的长期归类方式。
- 分组相当于长期归类能力；置顶继续保留。
- 置顶内容不受保存期限影响；取消置顶后，如果已经超过保存期限，下次清理时会按普通历史清理。
- 普通历史允许直接编辑；用户编辑提交后更新原记录内容，不新增记录。
- 第二版先做敏感 App 忽略和敏感内容遮罩，暂缓本地加密；敏感遮罩默认关闭，但需要引导用户了解如何开启。

协作执行边界：

- 主控 Agent 不写业务代码、不亲自修 bug；用户反馈 bug 后只负责记录、复现、归类、定级、生成 Bug 修复任务卡和调度。
- 产品规则冲突必须交给产品规则 Agent，并由用户确认后再进入实现或修复。
- 每次处理 bug、返工或新增功能前，必须读取 `docs/V2_FEEDBACK_AND_GUARDS.md`，避免破坏已确认产品行为和功能守卫。
- 非阻塞产品体验项写入 `docs/V2_OPTIMIZATION_BACKLOG.md`，不得只保留在会话上下文中。

## 3. 核心概念

### 3.1 普通历史

普通历史是用户复制产生的临时记录。

规则：

- 继续按保存期限自动清理。
- 可以搜索、预览、复制、粘贴、删除。
- 可以置顶。
- 可以加入分组形成长期归类。

### 3.2 置顶

置顶是临时排序能力，不等于永久保存。

规则：

- 置顶内容显示在普通历史最左侧。
- 置顶内容不受普通保存期限清理。
- 用户可以取消置顶。
- 取消置顶后，如果该内容已经超过保存期限，下次清理时按普通历史清理。
- 置顶不自动进入分组。

### 3.3 收藏（已废弃）

收藏不是第二版后续范围。

规则：

- 删除收藏字段、收藏筛选、星标、收藏快捷键和收藏菜单。
- 旧收藏数据不进入兼容范围，可以完全清空。
- 后续长期归类统一由分组承担。

### 3.4 分组

分组是用户主动归类长期内容的方式，类似文件夹。

规则：

- 用户可以创建、重命名、删除分组。
- 用户可以修改分组颜色。
- 用户可以选择分组图标，也可以同时设置颜色和图标。
- 分组图标来源为系统图标 + 轻贴内置图标库，暂不支持自定义图片。
- 一个内容默认只属于一个分组。
- 未分组内容仍显示在“全部剪切板”中，不单独引入收藏态。
- 无内容分组可直接删除，不需要确认。
- 有内容分组删除时使用普通确认弹窗，显示会删除多少条内容且无法恢复。
- 有内容分组删除确认弹窗的危险按钮文案为“删除分组和内容”。
- 分组支持拖拽排序。

建议：

- 第二版先做单层分组，不做多级文件夹，降低复杂度。
- 普通历史可以直接加入分组；加入分组后由分组承担长期归类语义。
- 普通历史加入分组时更新原记录分组归属，不复制新记录。
- 分组入口参考 Paste / Pinboard，放在主窗口顶部，以不同颜色按钮区分；右侧 `+` 用于新建分组。
- 分组数量较多时，顶部分组栏横向滚动，并在右侧提供更多分组入口。

## 4. 第二版功能建议

### 4.1 SQLite 数据库

目标：

- 支持几千到几万条历史记录长期使用。
- 搜索和筛选更稳定。
- 后续同步、分组和内容增强有可靠数据基础。

用户价值：

- 长期使用不容易卡顿。
- 数据维护更清晰。
- 更容易做备份和恢复。

已确认规则：

- App 后续开发采用 SQLite-only，不再保留 JSON 主存储或 JSON 迁移路径。
- 第二版数据健康检查优先支持 SQLite。
- 第二版导入导出默认使用 SQLite 备份包。
- SQLite 备份包扩展名为 `.clipeasebackup`。
- 导出备份包时由用户选择是否包含图片、富文本等附件。
- 导出备份包时，“包含附件”默认勾选。
- 导出备份成功后显示提示，用户点击“显示”后再在 Finder 中定位文件。
- 导入备份包遇到重复记录时弹窗让用户选择处理方式。
- 导入备份包遇到重复记录时，弹窗默认推荐“跳过重复”。
- 开发测试数据入口移到设置页隐藏入口。
- 开发测试数据入口通过在设置页连点版本号 5 次显示。
- SQLite 默认搜索路径根据实际性能动态决定。
- 数据健康检查发现问题后提供“一键修复”。
- 数据健康检查“一键修复”前每次都确认。
- 数据健康检查“一键修复”完成后生成简短报告。

### 4.2 收藏和永久保存（已废弃）

目标：

- 收藏和永久保存不再作为第二版独立功能推进。

废弃范围：

- 收藏 / 取消收藏。
- 收藏筛选。
- 星标 UI。
- 管理收藏。
- 收藏数据兼容、迁移和清理保护。

### 4.3 分组管理

目标：

- 用户可以把内容放进不同分组，分组承担长期归类语义。

示例分组：

- 常用文案
- 代码片段
- 设计素材
- 链接资料
- 客服回复

交互建议：

- 主窗口顶部显示分组按钮，按不同颜色区分。
- 分组栏右侧 `+` 表示新建分组。
- 新建分组默认名称为“新分组”，默认颜色来自固定预设色板。
- 新建分组默认图标为随机图标。
- 点击 `+` 新建分组后，用户可以立即修改分组名、颜色和图标，交互参考 Paste。
- 新建分组后不自动进入新分组，主窗口仍停留在当前分组。
- 分组可以重命名、修改颜色、选择图标。
- 分组重命名支持右键分组按钮和双击分组按钮。
- 分组颜色和图标修改支持右键分组按钮和分组管理面板。
- 分组颜色允许使用系统取色器自定义。
- 分组图标允许搜索。
- 分组顶部按钮默认不显示数量，悬停时显示数量。
- 分组里的内容按加入分组时间倒序排列。
- 更多菜单保留“分组管理”入口，用于集中管理名称、颜色、图标和删除。
- 更多分组入口点击右侧“更多”按钮弹出菜单。
- 更多分组超过 10 个时显示分组搜索。
- 卡片右键支持“加入分组”。

### 4.4 更强搜索

目标：

- 搜索不仅按内容，还能按来源、类型、时间和分组过滤。

建议能力：

- 按来源 App 搜索。
- 按内容类型筛选：文字、图片、链接、颜色、富文本。
- 按时间范围筛选：今天、最近 7 天、最近 30 天、自定义范围。
- 只搜某个分组。
- 搜索结果继续保持黄色背景高亮。

交互规则：

- 筛选入口放到搜索框右侧，参考 Paste 的筛选位置和筛选弹窗。
- 搜索框未展开时，按 `Command + F` 展开搜索框并聚焦。
- 打开搜索框后，再次按 `Command + F` 弹出筛选面板。
- 筛选面板打开时，再次按 `Command + F` 关闭筛选面板并聚焦搜索框。
- 筛选面板按分类展示，例如类型、来源 App、日期、设备等。
- 筛选面板采用悬浮弹层，带指向搜索框右侧筛选按钮的小三角。
- 来源 App 按最近使用排序。
- 类型筛选在面板中一次只能选择一种类型。
- 搜索框支持多个筛选 token 并存，例如类型 + 来源 App + 日期。
- 筛选 token 支持两种删除方式：点击 token 上的关闭按钮，或光标在 token 后方时按 Backspace 删除。
- 多个筛选 token 在搜索框内横向展示，超出搜索框宽度时横向滚动。
- 搜索框横向滚动时，输入光标必须始终保持可见。
- 筛选 token 不支持拖拽排序，按固定顺序展示：类型、App、日期、分组。
- 固定顺序中如果没有某一类条件，后续 token 前移，保持紧凑。
- 筛选 token 点击本体无动作，只能通过关闭按钮、Backspace 或筛选面板修改。
- 筛选面板不长期记忆上次打开位置和滚动位置。
- 筛选面板每次打开回到顶部。
- 筛选面板顶部不显示已选条件摘要。
- 设备筛选默认不显示；只有未来开启同步预研相关功能后才显示。
- 主窗口默认只显示搜索图标，点击搜索图标或直接输入后展开搜索框。
- 搜索框展开后自动聚焦，光标位于末尾，不选中已有内容。
- 搜索框中筛选 token 在前，关键词在后。
- 点击搜索框清空按钮时，同时清空关键词和全部筛选 token。
- 搜索框清空按钮在有关键词或筛选 token 时显示。
- 点击清空按钮后保持搜索框展开并聚焦；按 Esc 仍按分层关闭规则执行。
- Esc 规则：如果筛选面板打开，先关闭筛选面板；然后清空搜索框内容和筛选 token；然后关闭搜索框；最后关闭主窗口。
- Esc 清空搜索内容时，同时清空关键词和筛选 token。
- 搜索框展开后，点击其他非搜索区域关闭搜索框。
- 筛选面板打开时，点击主窗口卡片会先关闭筛选面板，再选中卡片。
- 搜索框展开且没有关键词和筛选 token 时，点击主窗口外部直接关闭主窗口。
- 筛选面板打开时，点击主窗口外部同时关闭筛选面板和主窗口。
- 点击清空按钮后不显示全局提示。
- 搜索框聚焦时，左右方向键优先移动文本光标。
- 搜索框聚焦时，上下方向键按系统文本框默认行为处理。
- 搜索框聚焦时，按回车进入卡片选择。
- 搜索框光标位于文本末尾时，按方向右键或方向下键进入卡片选择。
- 进入卡片选择后，搜索框保持展开，卡片显示选中态。
- 从卡片选择返回搜索框的方式：点击搜索框或按 `Command + F`。
- 搜索框聚焦时按 Tab 进入卡片列表；卡片列表中再次按 Tab 返回搜索框，光标回到原位置。
- 卡片列表中按 `Shift + Tab` 反向切换卡片。
- 搜索框有中文输入法候选时，回车优先确认候选词；没有候选框时，回车进入卡片选择。
- 卡片选择状态下继续输入文字，会回到搜索框并追加输入。
- 卡片选择状态下继续输入文字后，保留当前卡片选中态，直到搜索结果更新。
- 搜索结果更新后，自动选中第一条结果。
- 卡片选择状态下按 Delete 删除选中卡片。
- 卡片选择状态下按 Backspace 删除选中卡片。
- Delete / Backspace 删除卡片不弹确认，直接删除。
- 删除当前卡片后选中右侧下一张。
- 删除卡片后显示全局提示“已删除 撤销”，持续 8 秒。
- 删除支持撤销。
- 撤销后卡片恢复到原位置。
- 删除分组里的内容时，从所有地方彻底删除。

Stage 8 收口裁定：

- 以上 Delete / Backspace 删除、删除撤销、删除后恢复位置、分组内容彻底删除和附件清理相关规则不进入阶段 8 剩余低风险 UI 收口。
- 删除 / 撤销 / 附件生命周期属于红线范围，必须移入独立产品 + 架构 + 测试任务卡后再实现。
- 阶段 8 第二批 PASS 并 build / run `1.0.13 (260514.2108)` 后，阶段 8 建议收口；下一步建议进入阶段 9 文件卡片 / Quick Look 前置方案。
- 撤销图片删除时需要恢复已删除的本地图片附件。

### 4.5 历史内容编辑

目标：

- 文本和富文本内容可以再次编辑。

规则：

- 普通历史允许直接编辑。
- 用户编辑提交后，更新原记录内容，不新增历史记录。
- 如果原记录属于分组或置顶，编辑后仍保留原分组和置顶状态。
- 编辑窗口需要有明确取消和保存，取消不修改原记录。
- 编辑记录不保留编辑前版本历史。
- 右键菜单“编辑”对文本、链接、颜色卡片显示；图片暂不显示编辑入口。
- 颜色卡片编辑同时支持输入 HEX 和使用系统颜色选择器。
- 颜色卡片编辑保存后只更新历史记录，不立即复制新颜色到剪贴板。
- 颜色卡片编辑保存后显示全局提示“颜色已更新”。
- 颜色卡片编辑保存后只刷新颜色预览区域，不刷新卡片顶部标题栏颜色；标题栏仍按来源 App 图标颜色显示。

### 4.6 批量操作（已废弃）

目标：

- 批量操作不再作为第二版后续范围推进。

废弃范围：

- 多选删除。
- 多选移动到分组。
- 多选导出。
- 管理模式入口、多选状态、已选数量和批量操作栏。

### 4.7 隐私和安全增强

目标：

- 降低敏感内容被误记录的风险。

建议能力：

- 默认建议忽略密码管理器。
- 增加敏感关键词或格式识别，例如验证码、银行卡、Token。
- 对敏感内容只显示遮罩，点击后再显示。
- 设置某些 App 只记录文字、不记录图片。

规则：

- 第二版先做敏感 App 忽略和敏感内容遮罩。
- 敏感内容遮罩默认关闭。
- 需要建立引导，说明敏感遮罩能做什么、如何开启、开启后如何查看被遮罩内容。
- 敏感遮罩开启后，点击被遮罩内容需要通过系统密码或 Touch ID 验证后显示。
- 敏感遮罩验证通过后，内容显示 30 秒。
- 敏感规则由系统内置规则和用户自定义关键词共同组成。
- 敏感内容记录规则默认记录但遮罩。
- 敏感内容是否记录原内容由用户按规则选择。
- 本地加密暂缓，等 SQLite、搜索和分组稳定后再评估。

### 4.8 链接卡片增强

目标：

- 链接卡片更接近真实网页预览。

建议能力：

- 获取网页标题。
- 获取网页图标。
- 获取网页描述。
- 失败时显示简洁占位。
- 支持复制标题、复制 URL、复制 Markdown。
- 支持 `Command + E` 编辑 URL 地址；链接编辑窗口只编辑 URL，不增加标题和备注字段。
- 链接编辑窗口参考 Paste：顶部取消/保存，中间编辑 URL，底部显示当前 URL，并提供“在 默认浏览器 中打开”按钮。
- “在 Chrome 中打开”“在 Edge 中打开”等按钮文案需要按系统默认浏览器动态显示。
- 链接 URL 编辑保存后，后台重新抓取网页标题和图标。
- 链接 URL 编辑保存后，立即复制新 URL 到剪贴板。
- 链接 URL 编辑保存后显示全局提示“链接已更新并复制”。

### 4.9 图片能力增强

目标：

- 图片不只是历史记录，也可以被分组长期归类。

建议能力：

- 图片加入分组。
- 查看原图。
- 复制为图片。
- 复制为文件。
- 导出图片。
- 删除图片卡片时立即删除本地图片附件。

### 4.10 文件卡片和系统级预览

Stage 9 第一批 preflight：

本节覆盖任务卡 `V2-PRODUCT-S9-FILE-CARD-QUICKLOOK-PREFLIGHT-001`。Stage 9 第一批只做文件卡片 / Quick Look 的产品前置方案和小步 MVP 边界，不一次性实现全量文件能力。

目标：

- 用户复制本地文件时，轻贴也能记录文件历史，并尽量按 macOS 原生预览能力展示内容。
- 第一批先验证“记录路径 -> 展示文件卡片 -> Quick Look 预览 -> 基础文件操作”的闭环。
- 第一批不改变删除 / 撤销 / 附件生命周期语义。

第一批 MVP 范围：

- 支持记录从 Finder 或其他 App 复制的 1 个或多个本地文件路径。
- 支持单文件卡片和多文件卡片基础展示。
- 支持文件卡片加入分组；不恢复收藏、管理模式、多选或批量操作。
- 支持通过预览窗口调用系统 Quick Look 能力预览单文件。
- 支持多文件预览窗口展示文件列表，并允许用户从列表中选择单个文件预览。
- 支持路径失效、不可预览、加载慢和 Quick Look 失败的基础回退状态。
- 支持基础操作：复制 / 粘贴文件引用、在 Finder 中显示、复制路径。
- 搜索第一批只匹配文件名和完整路径的普通字符串搜索。

规则：

- 用户复制 1 个或多个文件时，记录文件本地路径。
- 第一批只记录原文件路径和必要展示元数据，不复制原文件内容到轻贴附件目录。
- 文件卡片必须记录完整路径，不允许只记录文件名。
- 文件卡片路径第一批不隐藏用户名。
- 文件卡片显示文件扩展名。
- 文件卡片不记录 security-scoped bookmark，不主动申请长期文件访问权限。
- 文件卡片不需要单独设置开关，默认记录。
- 文件卡片支持加入分组。
- 文件卡片不参与敏感遮罩。
- 文件卡片不支持删除原文件；删除历史记录不影响原文件。
- 删除文件历史记录只删除轻贴里的历史记录。
- 本批不做删除撤销、不做删除后恢复位置、不做附件清理语义变化。
- 本批不做文件副本导出，不做备份包内包含文件副本。

卡片展示规则：

- 单文件标题显示文件名，包含扩展名。
- 多文件标题显示数量，例如“3 个文件”。
- 单文件主体显示系统缩略图；缩略图不可用或生成失败时显示系统文件图标。
- 多文件主体第一批显示堆叠文件图标，优先使用前 3 个文件的系统图标；暂不生成复杂拼贴缩略图。
- 单文件底部显示完整路径，最多 2 行，超出 2 行省略。
- 多文件底部显示第一个文件所在路径或“多个位置”；完整路径列表进入预览窗口或“复制路径”结果。
- 来源 App 显示复制来源 App 图标，例如 Finder；卡片顶部颜色第一批可沿用现有来源 App 主色规则，不单独调色。
- 单文件路径失效时，路径文字使用错误状态颜色，并显示“文件已移动或删除”状态。
- 多文件中部分路径失效时，在卡片上标记失效数量，例如“1 个不可用”；全部失效时显示整体失效状态。
- 文件卡片的分组入口沿用现有“加入分组 / 移动到分组”单条交互。

Quick Look / 预览窗口规则：

- 单文件预览顶部标题显示文件名。
- 单文件预览优先调用 macOS Quick Look 展示图片、PDF、文档、视频、音频等系统可预览内容。
- 不可预览文件显示系统文件图标和基础信息。
- 基础信息第一批显示文件名、完整路径、文件类型、大小和修改时间；如果读取失败则显示可取得的信息。
- 路径失效时不删除历史记录；预览窗口显示系统文件图标和“文件已移动或删除”。
- Quick Look 加载慢时显示加载中状态。
- Quick Look 加载失败时回退到系统文件图标、基础信息和“在 Finder 中显示”入口。
- 多文件预览窗口第一批展示文件列表，列表显示文件图标、文件名和路径状态。
- 多文件预览中选择某个有效文件后，在同一预览窗口中尝试 Quick Look 该文件。
- 多文件中不可预览或路径失效的文件按单文件回退规则显示。
- 文件路径失效后不提供“重新定位文件”。

第一批交互：

- 双击、回车或 `Command + 1-9`：优先粘贴文件引用；如果目标 App 不支持文件引用，则回退粘贴文件名。
- 多文件双击、回车或 `Command + 1-9`：优先粘贴全部文件引用；如果目标 App 不支持文件引用，则回退粘贴全部文件名，每行一个。
- `Command + C` 或右键“复制”：复制文件引用；失败时回退复制文件名。
- 右键菜单增加“在 Finder 中显示”。
- 右键菜单增加“复制路径”。
- 多文件“复制路径”复制全部路径，每行一个。
- 预览窗口内第一批提供“在 Finder 中显示”和“复制路径”。

后续批次暂缓：

- 从文件卡片拖出到 Finder 或其他 App。
- 文件预览窗口内“打开文件”。
- 系统分享。
- 文件副本导出。
- 备份包包含文件副本。
- 文件卡片拼音搜索。
- 文件路径 FTS、专用索引或搜索 Repository 下沉。
- 多文件列表排序自定义。
- 多文件列表显示每个文件大小。
- 文件路径隐私遮罩或用户名隐藏。
- security-scoped bookmark 或重新定位文件。

搜索第一批规则：

- 文件卡片参与搜索，字段仅包括文件名和完整路径。
- 搜索使用当前普通字符串搜索能力；暂不要求拼音、FTS 或新增索引。
- 文件类型筛选如果当前类型系统已支持，可把文件作为独立类型接入；如果类型筛选尚未稳定，不作为第一批门禁。

用户确认红线：

- 是否确认文件卡片记录完整路径，而不是只记录文件名。
- 是否确认完整路径第一批直接显示用户名，例如 `/Users/name/...`，不做隐藏。
- 是否确认第一批不记录 security-scoped bookmark，因此文件移动、权限变化或 App 重启后可能无法访问原文件，只显示失效状态。
- 是否确认第二版第一批备份不包含原文件副本，只备份文件路径历史。
- 是否确认删除历史记录永远不删除原文件。
- 是否确认本批不做删除撤销、不做附件清理语义变化。
- 是否确认文件卡片默认记录，不增加单独开关。

### 4.11 iCloud 同步（已取消）

第二版不实现 iCloud 同步，也不保留 Stage 10 作为当前交付范围。

原因：

- 免费账号不能支撑可分发、可用的正式 iCloud 同步产品。
- 同步会引入冲突、隐私、加密和附件传输问题，不符合当前收口阶段目标。

结论：

- 不做正式 iCloud 同步。
- 不做同步开关、设备筛选 UI、同步状态 UI 或 CloudKit / iCloud runtime。
- 不做附件上传下载、端到端加密、跨设备删除同步或冲突合并 runtime。
- 文件卡片只保留本机路径历史语义，不扩展为跨设备同步。
- 若未来重新评估云同步，需另起新范围，不沿用第二版当前计划。

### 4.11 富文本卡片展示

目标：

- 如果内容是富文本，卡片预览区域应显示带格式的富文本，而不是退化成纯文本。

建议规则：

- 卡片中按照复制时的富文本格式显示，包括字体样式、字号、文字颜色、背景色等可安全渲染的格式。
- 卡片预览需要限制渲染复杂度，避免大量富文本卡片影响主窗口流畅度。
- 搜索命中仍需高亮，但不能破坏富文本原格式。
- 富文本编辑保存后尽量保留原富文本格式。

### 4.12 新历史后的窗口位置

规则：

- 如果有新的剪贴板历史产生，下次打开主窗口时回到第一条卡片。
- 如果没有新历史，主窗口保留用户上次横向浏览位置。

原因：

- 有新内容时，用户最可能想看最新记录。
- 无新内容时，保留位置更符合继续浏览历史的预期。

### 4.13 快捷键体系补全

目标：

- 右键菜单、系统菜单、主界面更多菜单中的常用功能统一显示快捷键。
- 主窗口右侧 `...` 下拉菜单和菜单栏右键下拉菜单使用同一套菜单结构和快捷键。
- 卡片右键菜单中的已有快捷方式必须展示出来，并用分割线分组。

已建议快捷键：

- `Command + ,`：打开设置。
- `Command + E`：编辑当前文本或链接卡片。
- `Command + T`：暂停 / 恢复轻贴记录。
- `Command + D`：删除当前选中卡片。

待补充候选：

- 移动到分组。
- 导出当前选中内容。

卡片右键菜单快捷键展示：

- 预览：`Space`
- 粘贴：`⏎`
- 粘贴为纯文本：`⇧⏎`
- 复制：`⌘C`
- 复制纯文本：`⇧⌘C`

卡片右键菜单分类建议：

- 粘贴类：粘贴、粘贴为纯文本。
- 复制类：复制、复制纯文本、链接复制地址、链接复制 Markdown、颜色复制 HEX / RGB。
- 管理类：预览、编辑、置顶、移动到分组。
- 危险操作：删除。

### 4.14 窗口层级

规则：

- 主窗口调出时需要保持在最前。
- 预览窗口打开后，预览窗口必须在主窗口前方。
- 点击主窗口外部仍按当前规则关闭主窗口；需要特别处理设置、帮助、新建文本等轻贴自己的窗口。

### 4.15 新建文本入口

规则：

- 用户通过主窗口 `...` 菜单点击“新建文本”后，主窗口应隐藏。
- 新建文本窗口独立显示，不因主窗口隐藏而关闭。
- 从 `...` 新建文本创建的内容默认归属当前选中的分组；如果当前在“全部剪切板”分组，则进入普通历史。
- 新建文本窗口中允许选择分组。
- 新建文本创建成功后，打开主窗口，并显示和选中新记录。

### 4.16 全局提示层

目标：

- 所有操作提示从主窗口左侧迁移到统一的提示层。

样式规则：

- 位置：底部中间靠上一点。
- 层级：最高层，不被主窗口、预览窗口、设置页覆盖。
- 外观：无边框、圆角、浅色半透明背景。
- 内容：始终显示来源 App 图标和短提示，例如“Paste 暂停”“Chrome 已加入分组”“已复制”。
- 动画：淡入淡出。
- 时长：约 1 秒后自动关闭。

建议：

- 提示层只用于短反馈，不承载需要用户选择的确认操作。
- 需要确认的危险操作仍使用系统确认弹窗或专用确认 UI。

### 4.17 主窗口顶部简化

目标：

- 主窗口顶部参考 Paste，保持简洁，不重复展示可在设置中操作的状态项。

规则：

- 默认剪切板历史分组代表全部剪切板内容，可参考 Paste 的 Pinboard 表达。
- 主窗口顶部不重复展示“轻贴文本”“关闭按钮”“自动粘贴”“记录中”“永久记录”等状态项。
- 搜索框、筛选按钮、顶部字体和图标需要比第一版更大，更易点击。
- 主窗口右侧更多按钮只显示 `...`，不显示向下箭头。
- 设置中可以操作的长期配置，不在主窗口顶部重复常驻展示。

建议顶部结构：

- 左侧或中间区域：搜索框和筛选按钮。
- 顶部分组区域：彩色分组按钮和 `+` 新建分组。
- 右侧：`...` 更多菜单。

## 5. 建议优先级

### 第二版第一阶段：数据和分组基础

- SQLite-only 数据库基础。
- 第二版正式开始写代码时，第一步先做 SQLite 主存储和数据库基础。
- 分组基础模型。
- 更强搜索的基础字段准备。

### 第二版第二阶段：分组和主窗口体验

- 分组管理界面。
- 加入分组。
- 内容编辑。
- 快捷键体系补全。
- 全局提示层。

### 第二版第三阶段：内容增强

- 链接卡片增强。
- 图片和文件操作增强。
- 富文本卡片展示。
- 隐私忽略和敏感遮罩。

### 第二版第四阶段：同步预研

- iCloud 数据结构评估。
- 附件同步策略评估。
- 冲突解决策略评估。

## 6. 第二版暂不建议马上做

- iCloud 正式同步。
- 端到端加密。
- OCR 图片文字识别。
- 多级文件夹。
- 插件系统。
- 团队共享。

这些能力价值明确，但复杂度高，建议等第二版核心数据层和管理能力稳定后再推进。

## 7. 待用户继续确认的问题

- 多文件卡片文件列表的排序规则。
- 多文件卡片预览列表里是否显示每个文件大小。
- 文件卡片“打开文件”失败时的提示文案。
- 文件卡片系统分享失败时的回退行为。
- 文件卡片拼音搜索是否只支持文件名，还是文件路径也支持。
