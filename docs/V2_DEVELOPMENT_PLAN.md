# 第二版开发计划草案

## 1. 推进原则

第二版继续小步推进，每轮最多实现少量同类功能。

原则：

- 先方案，后代码。
- 先数据安全，后界面增强。
- 先迁移和备份，后替换主存储。
- 收藏、分组、搜索都必须建立在稳定数据层之上。
- iCloud 同步先预研，不进入第二版第一阶段实现。

## 2. 阶段 0：第二版方案确认

目标：

- 确认第二版产品范围。
- 确认 SQLite、收藏、分组、更强搜索的优先级。
- 确认暂缓项。

完成标准：

- `docs/V2_PRODUCT_PLAN.md` 经用户确认。
- `docs/V2_TECHNICAL_PLAN.md` 经用户确认。
- `docs/V2_DEVELOPMENT_PLAN.md` 经用户确认。

## 3. 阶段 1：SQLite 基础和迁移验证

目标：

- 建立 SQLite 存储层。
- 设计表结构。
- 从现有 JSON 做只读迁移验证。

完成标准：

- 不影响第一版现有 JSON 数据。
- 可以把 JSON 历史导入 SQLite 测试库。
- 迁移失败不会影响 App 启动。
- 有迁移日志和错误统计。

## 4. 阶段 2：Repository 抽象

目标：

- 把 UI 和存储细节隔离。
- 为 JSON 到 SQLite 切换做准备。

完成标准：

- 历史查询、添加、删除、置顶、清理都通过统一接口。
- 旧 JSON 实现仍可工作。
- SQLite 实现可以在开发开关下验证。

## 5. 阶段 3：SQLite 成为主存储

目标：

- 将 SQLite 切换为主存储。
- JSON 作为迁移来源和安全备份。

完成标准：

- App 正常记录、搜索、预览、粘贴。
- 历史重启后保留。
- 导入导出逻辑适配 SQLite。
- 数据健康检查支持 SQLite。

## 6. 阶段 4：收藏 / 永久保存

目标：

- 实现收藏和取消收藏。
- 收藏独立于置顶。
- 收藏内容不被普通保存期限清理。

完成标准：

- 右键菜单可收藏。
- 顶部筛选可查看收藏。
- 收藏内容可取消收藏。
- 清理普通历史不会误删收藏附件。

## 7. 阶段 5：分组基础

目标：

- 实现单层分组。
- 收藏内容可加入分组。

完成标准：

- 可创建、重命名、删除分组。
- 可将收藏内容移动到分组。
- 删除分组时可选择移动到未分组或删除内容。
- 分组筛选可用。

## 8. 阶段 6：更强搜索

目标：

- 搜索支持来源 App、类型、时间范围、收藏、分组组合条件。

完成标准：

- 搜索结果完整。
- 大量历史下输入不卡顿。
- 高亮和筛选状态清晰。
- 搜索不会牺牲数据完整性。

## 9. 阶段 7：编辑和批量管理

目标：

- 收藏文本可编辑。
- 支持多选和批量操作。

完成标准：

- 收藏文本编辑后可再次粘贴。
- 批量删除、收藏、移动到分组可用。
- 批量操作有确认和撤销策略。

## 10. 阶段 8：内容增强

目标：

- 链接卡片增强。
- 图片操作增强。
- 隐私和敏感内容能力增强。

完成标准：

- 链接标题、图标、描述更稳定。
- 图片可导出、查看原图、复制为文件。
- 忽略 App 和敏感遮罩能力清晰可控。

## 11. 阶段 9：iCloud 同步预研

目标：

- 不实现正式同步，只产出技术预研和风险结论。

完成标准：

- 明确是否适合使用 CloudKit。
- 明确附件同步策略。
- 明确冲突解决策略。
- 明确隐私和加密要求。

## 12. 当前待确认

- 置顶内容是否永不清理。
- 取消收藏后内容如何处理。
- 普通历史是否必须先收藏才能进入分组。
- 普通历史是否允许直接编辑。
- 多选操作入口采用快捷键点选还是管理模式。
- 第二版是否先做忽略 App 和敏感遮罩，暂缓本地加密。
