## 0. 2026-05-14 新基线覆盖说明

本节为最新用户确认基线，覆盖本文早期阶段描述中与之冲突的内容。后续 Agent 若发现其他章节与本节冲突，以本节为准，并先同步文档再开发。

- 第二版当前基线为 SQLite-only；旧 JSON 数据代码和 SQLite 迁移代码可以删除，旧数据可清空。
- 旧 JSON 数据代码、JSON Repository、JSON 到 SQLite 迁移代码不再作为运行时能力维护。
- 不再实现收藏字段、收藏代码或收藏 UI。
- 不再实现收藏快捷键、批量收藏、收藏筛选或收藏空状态。
- 不再实现管理模式、多选或批量操作；已删除的管理模式不得恢复。
- 置顶和分组保留。
- “加入分组 / 移动到分组”不能重新引入收藏语义。
- 备份导入安全修复、加入分组 picker、历史卡片新剪切板定位 / 右键选中 / 顶部边框修复已通过 Test / Review / Acceptance，属于阶段 7 后的新基线组成部分。
- Bugfix Agent 已存在；主控 Agent 只负责调度，不写业务代码。

阶段边界结论：

- 阶段 7 当前不再有必须因旧收藏、旧管理模式或旧 JSON 迁移收口的技术门禁。
- 阶段 7 剩余门禁只允许来自真实回归、文档同步、测试脚本清理或用户新反馈 bug。
- 允许进入阶段 8“主窗口体验细节”，但首批任务必须限定为低风险 UI / 焦点 / 窗口层级 / 全局提示收口，不夹带数据层重构。
- 阶段 8 开工前，任务卡必须显式写入“不得恢复收藏 / 管理模式；不得恢复 JSON 迁移运行时路径”。
- 后续每个阶段开始前，主控 Agent 必须先调用 V2 测试计划 Agent 检查测试 / 验收门禁是否完整。
- 后续每次处理 bug、返工或新增功能前，主控 Agent 必须读取 `docs/V2_FEEDBACK_AND_GUARDS.md`。
- 主控 Agent 不写业务代码、不亲自修 bug；用户反馈 bug 后只负责记录、复现、归类、定级、生成 Bug 修复任务卡和调度。
- Bug 修复任务卡必须包含关联历史反馈、关联功能守卫、受影响功能、不得回归项和最小回归测试；修复后测试 Agent 必须回归原失败路径和相关功能守卫。
- 非阻塞项写入 `docs/V2_OPTIMIZATION_BACKLOG.md`；调度、沟通、文件锁、冲突、bug 修复和功能守卫记录写入 `docs/V2_AGENT_RUNBOOK.md`。

## 1. 推进原则

第二版继续小步推进，每轮最多实现少量同类功能。

原则：

- 先方案，后代码。
- 先数据安全，后界面增强。
- 当前实现以 SQLite-only 为基线，旧 JSON 和迁移路径不再作为新功能前置条件。
- 分组、置顶和搜索都必须建立在稳定数据层之上。
- iCloud 同步已取消，不进入第二版规划。
- 第二版已确认的产品规则必须先写入方案，再进入实现。

## 2. 实现前最终规则

- 第二版方案用户确认后即可进入实现阶段。
- 第二版第一批代码顺序：SQLite 基础、Repository 抽象、测试计划补细、搜索 / 筛选重构。
- 第二版实现不新建开发分支，直接在 `main` 上小步提交。
- 第二版开始写代码后，每个阶段完成后再编译运行给用户测试；单个小改动优先跑检查。
- 第二版正式开始实现时，版本号从 `2.0.0(时间戳)` 开始。
- 实现前必须确认文档齐备：`docs/V2_PRODUCT_PLAN.md`、`docs/V2_TECHNICAL_PLAN.md`、`docs/V2_DEVELOPMENT_PLAN.md`、`docs/V2_TEST_PLAN.md`。

## 4. 阶段 1：SQLite 基础

目标：

- 建立 SQLite 存储层。
- 设计表结构。
- 直接以 SQLite 作为 App 主存储。

完成标准：

- 数据库文件名为 `ClipEase.sqlite`。
- 新库创建、schema 版本、基础读写和失败重建路径可验证。
- 不再实现或保留 JSON 导入、JSON 删除、迁移日志和迁移结果 UI。
- 第二版后续阶段从 SQLite-only 基线继续推进。

## 5. 阶段 2：Repository 抽象

目标：

- 把 UI 和存储细节隔离。
- 为 SQLite-only 数据访问做准备。

完成标准：

- 历史查询、添加、删除、置顶、清理都通过统一接口。
- 不保留旧 JSON 实现。
- SQLite 实现直接作为主实现验证。

## 6. 阶段 3：SQLite 成为主存储

目标：

- 将 SQLite 切换为主存储。
- 删除 JSON 兼容和迁移残留。

完成标准：

- App 正常记录、搜索、预览、粘贴。
- 历史重启后保留。
- 导入导出逻辑适配 SQLite，默认使用 SQLite 备份包，扩展名为 `.clipeasebackup`。
- 导出备份包时由用户选择是否包含图片、富文本等附件。
- 导出备份包时，“包含附件”默认勾选。
- 导出备份成功后显示提示，用户点击“显示”后再在 Finder 中定位文件。
- 导入备份包遇到重复记录时弹窗让用户选择处理方式。
- 导入备份包遇到重复记录时，弹窗默认推荐“跳过重复”。
- 数据健康检查优先支持 SQLite，发现问题后提供“一键修复”。
- 数据健康检查“一键修复”前每次都确认，完成后生成简短报告。
- 1,000 / 10,000 条测试数据入口移到设置页隐藏入口，通过连点版本号 5 次显示。

## 7. 阶段 4：收藏 / 永久保存（已废弃）

目标：

- 收藏功能、收藏字段、收藏筛选和星标 UI 不再进入第二版范围。

完成标准：

- 旧收藏代码和旧收藏数据兼容可以删除。
- 后续长期归类由分组承担。
- 置顶保留，不与收藏产生交互规则。

## 8. 阶段 5：分组基础

目标：

- 实现单层分组。
- 内容可加入分组。
- 主窗口顶部展示 Pinboard 风格分组按钮。

完成标准：

- 可创建、重命名、删除分组。
- 可修改分组颜色。
- 可选择分组图标，或使用颜色 + 图标组合。
- 分组图标来源为系统图标 + 轻贴内置图标库，暂不支持自定义图片。
- 分组颜色允许使用系统取色器自定义。
- 分组图标允许搜索。
- 顶部分组按钮按颜色区分，右侧 `+` 可新建分组。
- 顶部分组栏支持横向滚动，并在右侧提供更多分组入口。
- 分组顶部按钮默认不显示数量，悬停时显示数量。
- 分组里的内容按加入分组时间倒序排列。
- 新建分组默认名称为“新分组”，默认颜色来自固定预设色板，默认图标为随机图标，创建后立即允许用户修改名称、颜色和图标。
- 新建分组后不自动进入新分组，主窗口仍停留在当前分组。
- 分组重命名支持右键分组按钮和双击分组按钮。
- 分组颜色和图标修改支持右键分组按钮和分组管理面板。
- 有内容分组删除确认弹窗的危险按钮文案为“删除分组和内容”。
- 更多分组入口点击右侧“更多”按钮弹出菜单。
- 更多分组超过 10 个时显示分组搜索。
- 可将内容移动到分组。
- 普通历史执行“加入分组”时更新原记录分组归属，不复制新记录。
- 空分组删除不需要确认。
- 有内容分组删除时使用普通确认弹窗，显示会删除多少条内容且无法恢复。
- 分组支持拖拽排序。
- 分组筛选可用。

## 9. 阶段 6：更强搜索

目标：

- 搜索支持来源 App、类型、时间范围和分组组合条件。
- 搜索方案同时准备普通索引 + `LIKE` 和 FTS5。
- 筛选入口移动到搜索框右侧。
- 搜索框未展开时，按 `Command + F` 展开搜索框并聚焦。
- 搜索框打开后，再按 `Command + F` 弹出筛选面板。
- 筛选面板打开时，再按 `Command + F` 关闭筛选面板并聚焦搜索框。
- 搜索框支持多个筛选 token 并存。
- SQLite 基础完成后，优先推进搜索 / 筛选重构。

完成标准：

- 搜索结果完整。
- 大量历史下输入不卡顿。
- 高亮和筛选状态清晰。
- 搜索不会牺牲数据完整性。
- 默认搜索路径根据实际性能动态决定。
- 筛选面板按类型、来源 App、日期、设备等分类展示。
- 来源 App 按最近使用排序。
- 类型筛选一次只能选一种类型。
- 筛选 token 可通过关闭按钮或 Backspace 删除。
- 多个筛选 token 在搜索框内横向展示，超出宽度时横向滚动。
- 搜索框横向滚动时，输入光标必须保持可见。
- 筛选 token 不支持拖拽排序，按固定顺序展示：类型、App、日期、分组。
- 固定顺序中如果没有某一类筛选条件，后续 token 前移，保持紧凑。
- 筛选 token 点击本体无动作，只能通过关闭按钮、Backspace 或筛选面板修改。
- 筛选面板不长期记住上次打开位置和滚动位置。
- 筛选面板每次打开回到顶部。
- 筛选面板顶部不显示已选条件摘要。
- 设备筛选默认不显示，只有未来同步预研相关功能开启后才显示。
- 筛选弹层位置和样式参考 Paste，锚定搜索框右侧筛选按钮。

## 10. 阶段 7：编辑、快捷键和单条操作

状态：已按 SQLite-only / no favorite / no management 新基线重新收口。SQLite LIKE / FTS / Repository 查询下沉属于并行搜索性能专项，不改变阶段 7 正式主线定义。

目标：

- 普通历史文本可编辑。
- 文本/链接卡片支持 `Command + E` 编辑。
- 链接卡片编辑时编辑 URL 地址，并提供“在 默认浏览器 中打开”入口。
- 常用菜单命令补齐快捷键。
- 支持单条记录删除、置顶和移动到分组。
- 卡片右键菜单显示已有快捷键，并按类别用分割线分组。

完成标准：

- 普通历史编辑提交后更新原记录内容，不新增记录。
- 原记录如果属于分组或置顶，编辑后仍保留对应状态。
- 编辑记录不保留编辑前版本历史。
- 右键菜单“编辑”对文本、链接、颜色卡片显示；图片暂不显示编辑入口。
- 颜色卡片编辑同时支持输入 HEX 和使用系统颜色选择器。
- 颜色卡片编辑保存后只更新历史记录，不立即复制新颜色到剪贴板。
- 颜色卡片编辑保存后只刷新颜色预览区域，不刷新卡片顶部标题栏颜色。
- 颜色卡片编辑保存后显示全局提示“颜色已更新”。
- 链接 URL 编辑保存后，后台重新抓取网页标题和图标。
- 链接 URL 编辑保存后，立即复制新 URL 到剪贴板。
- 链接 URL 编辑保存后显示全局提示“链接已更新并复制”。
- 链接编辑窗口只编辑 URL，不增加标题和备注字段。
- 卡片右键菜单快捷键使用 macOS 符号格式，例如 `⌘C`、`⇧⌘C`、`⏎`。
- 编辑后的文本、链接和颜色记录可再次粘贴。
- 右键菜单、系统菜单和主窗口更多菜单中的常用命令快捷键一致。
- 主窗口右侧 `...` 菜单和菜单栏图标右键菜单快捷键同步。
- 卡片右键菜单显示预览 `Space`、粘贴 `Return`、粘贴为纯文本 `Shift + Return`、复制 `Command + C`、复制纯文本 `Shift + Command + C`。
- `Command + D` 删除当前选中记录。
- 不恢复 `Command + D` 收藏语义。
- 不恢复 `Command + M` 管理模式。
- 不恢复收藏、管理模式、多选或批量操作。
- 移动到分组使用稳定的单条分组选择器，不使用闪烁的二级菜单。
- 阶段 7 后续只允许处理已发现回归、文档同步和与当前编辑闭环直接相关的小修复。

## 11. 阶段 8：主窗口体验细节

目标：

- 有新剪贴板历史时，下次打开主窗口回到第一条卡片。
- 主窗口和预览窗口层级稳定。
- 从主窗口更多菜单打开新建文本时隐藏主窗口。
- 从主窗口更多菜单新建文本时，内容默认归属当前选中的分组；如果当前在“全部剪切板”分组，则进入普通历史。
- 新建文本窗口允许选择分组。
- 新建文本创建成功后，打开主窗口，并显示和选中新记录。
- 所有短提示迁移到统一全局提示层。
- 主窗口顶部参考 Paste 简化，移除设置页已有状态项的重复展示。
- 主窗口右侧更多按钮只显示 `...`。

完成标准：

- 没有新历史时，主窗口仍能恢复用户上次横向位置。
- 有新历史时，主窗口打开后定位到最新卡片。
- 预览窗口始终在主窗口前方。
- 全局提示层始终显示来源 App 图标和短提示，位于底部中间靠上一点，不被其他窗口遮挡，约 1 秒自动消失。
- 不在主窗口顶部常驻显示“自动粘贴”“记录中”“永久记录”等设置项。
- 搜索框、筛选按钮、顶部字体和图标尺寸比第一版更易点击。
- 主窗口默认只显示搜索图标，点击搜索图标或直接输入后展开搜索框。
- 搜索框展开后自动聚焦，光标停在末尾，不选中已有内容。
- 搜索框中筛选 token 在前，关键词在后。
- 点击搜索框清空按钮时，同时清空关键词和全部筛选 token。
- 搜索框清空按钮在有关键词或筛选 token 时显示。
- 点击清空按钮后保持搜索框展开并聚焦；按 Esc 仍按分层关闭规则执行。
- Esc 处理顺序为：关闭筛选面板、清空搜索内容和筛选 token、关闭搜索框、关闭主窗口。
- 搜索框展开后，点击其他非搜索区域关闭搜索框。
- 筛选面板打开时，点击主窗口卡片先关闭筛选面板，再选中卡片。

## 12. 阶段 9：内容增强

状态：Stage 8 已正式收口，Stage 9 已进入文件卡片 / Quick Look 前置方案。产品前置卡 `V2-PRODUCT-S9-FILE-CARD-QUICKLOOK-PREFLIGHT-001` 已给出产品 MVP；架构前置卡 `V2-ARCH-S9-FILE-CARD-QUICKLOOK-PREFLIGHT-001` 只输出架构方案，不写业务代码。

目标：

- 第一批先做文件卡片和系统级预览的小步 MVP。
- 验证“复制本地文件 -> 记录路径 -> 展示文件卡片 -> Quick Look 预览 -> 基础复制 / 粘贴 / Finder 操作”的闭环。
- 先确认 schema、Repository API、剪贴板捕获、Quick Look 生命周期、粘贴 / 拖出、搜索和隐私红线。
- 不一次性混入链接卡片增强、图片操作增强、富文本展示或敏感内容增强。
- 不改变删除 / 撤销 / 附件生命周期语义。

架构 preflight 完成标准：

- 确认需要新增 schema version，并新增 `clipboard_item_files` 子表保存 1 个或多个文件引用。
- 文件元数据最小集合为路径、文件名、扩展名、类型标识、大小、修改时间、目录标记、alias 标记、路径状态、检查时间和显示顺序。
- `clipboard_items.type` 增加 `file` 类型，置顶和分组继续沿用 item 维度能力；文件子表不承载置顶或分组字段。
- SQLite-only 基线不恢复 JSON 数据代码、JSON Repository 或 JSON 到 SQLite 迁移运行时路径。
- 迁移只新增文件卡片所需表 / 类型 / 最小索引，不改写既有文本、图片、富文本记录语义。
- 备份包如纳入文件卡片，只包含路径和元数据，不包含原文件副本。
- Clipboard 捕获明确处理 Finder 文件 URL、多个文件、目录、alias / symlink、网络盘、iCloud 占位和权限失败。
- UI 只能通过 Repository / view model 获取文件摘要和详情，不直接读 SQLite。
- Clipboard monitor、preview、paste executor 和 drag provider 不能绕过 Repository 更新或读取持久化数据。
- Quick Look 首批优先复用现有 preview window 生命周期；若使用 `QLPreviewPanel`，必须先完成焦点、Esc 和窗口层级 spike。
- 粘贴和拖出使用 `NSPasteboard` 文件 URL 类型；目标 App 不支持文件引用时，只承诺路径 / 文件名 fallback，不承诺精确检测目标 App 支持度。
- 首批搜索只做内存搜索文件名和路径，不做 LIKE / FTS / 拼音索引 / schema 搜索索引。
- 明确完整路径、用户名显示、不记录 security-scoped bookmark、删除历史不删原文件和备份不含文件副本等隐私边界。

第一批完成标准：

- 复制 1 个或多个本地文件时，记录文件本地路径。
- 只记录原文件路径和必要展示元数据，不复制原文件内容到轻贴附件目录。
- 文件卡片必须记录完整路径，不允许只记录文件名。
- 文件卡片路径第一批不隐藏用户名。
- 文件卡片显示文件扩展名。
- 文件卡片不记录 security-scoped bookmark。
- 文件卡片不需要单独设置开关，默认记录。
- 单文件卡片标题显示文件名，多文件卡片标题按数量显示，例如“3 个文件”。
- 单文件卡片内容显示系统缩略图；缩略图不可用或生成失败时显示系统文件图标。
- 多文件卡片主体显示堆叠文件图标，优先使用前 3 个文件的系统图标。
- 文件卡片底部路径最多显示 2 行，超出 2 行则省略。
- 多文件底部显示第一个文件所在路径或“多个位置”。
- 文件卡片的 App 来源图标显示来源 App 图标，例如 Finder。
- 文件预览窗口优先使用 macOS Quick Look 能力展示图片、文档、PDF 等系统可预览内容。
- 不支持系统预览的文件显示系统文件图标和基础信息。
- 基础信息第一批显示文件名、完整路径、文件类型、大小和修改时间；如果读取失败则显示可取得的信息。
- 文件路径失效时不删除历史记录；卡片底部路径变红，预览窗口显示文件图标和“文件已移动或删除”。
- 文件卡片支持加入分组；不恢复收藏。
- 文件卡片双击、回车或 `Command + 1-9` 时，优先粘贴文件引用；如果目标 App 不支持文件引用，则粘贴文件名。
- 文件卡片右键菜单增加“在 Finder 中显示”和“复制路径”。
- 文件卡片预览顶部标题显示文件名。
- 预览窗口内第一批提供“在 Finder 中显示”和“复制路径”。
- 文件卡片参与搜索，第一批只搜索文件名和完整路径。
- 文件卡片不参与敏感遮罩。
- Quick Look 预览加载慢时显示加载中状态。
- Quick Look 预览失败时回退到系统文件图标、基础信息和“在 Finder 中显示”入口。
- 多文件卡片的预览窗口展示文件列表，列表显示文件图标、文件名和路径状态。
- 多文件预览中选择某个有效文件后，在同一预览窗口中尝试 Quick Look 该文件。
- 多文件卡片双击、回车或 `Command + 1-9` 时粘贴全部文件引用。
- 文件路径失效后不提供“重新定位文件”。

- 文件卡片不支持删除原文件；删除历史记录不影响原文件。
- 多文件卡片中部分文件路径失效时，标记失效数量。
- 删除文件历史记录只删除轻贴里的历史记录。
