# 设计规范

## 1. 视觉原则

轻贴的视觉方向：

- 简洁
- 直观
- 清爽
- 高效
- 淡蓝色作为品牌基础色

可以参考 Paste 的交互效率和信息密度，但必须使用轻贴自己的原创视觉细节、文案和图标。

## 2. 主色

建议色彩：

- 品牌蓝：`#2F8CFF`
- 浅蓝背景：`#EAF4FF`
- 背景叠色：底部历史主窗口使用淡蓝纯色，优先保证整窗抽屉动画流畅。
- 正文深灰：`#20242A`
- 辅助灰：`#6B7280`
- 边框浅灰：`#D8E2EF`
- 危险红：`#E5484D`

## 3. 底部窗口

- 宽度占满屏幕。
- 高度固定。
- 背景使用纯色，不使用毛玻璃或渐变，避免整窗动画时触发透明合成和额外重绘。
- 打开和关闭必须是整个底部主窗口的上滑、下滑动画。
- 主窗口动画期间关闭阴影，并使用 `display: false` 移动窗口 frame，避免每帧强制刷新内容。
- 不允许使用截图或假画面替代真实窗口动画。
- 横向卡片列表使用懒加载，避免打开时一次性渲染全部历史。
- 主窗口首次弹出时优先渲染首屏附近卡片，动画结束后再补齐完整历史列表。
- 主窗口打开时预热前几张卡片的图片缩略图和来源 App 图标，降低首次显示延迟。
- 内容区横向滚动。
- 不做左侧分类栏。
- 顶部使用筛选和搜索。
- 默认搜索为图标状态，点击或输入时展开。
- 搜索框展开和收起使用宽度与透明度过渡，不能导致内容整体跳动。

## 4. 卡片

卡片：

- 竖向矩形。
- 固定宽度和高度。
- 圆角适中。
- 选中时使用品牌蓝描边。
- 卡片之间保持稳定间距。
- 不因为内容长短改变尺寸。

顶部标题栏：

- 颜色来自来源 App 图标主色。
- 提取失败时使用品牌蓝。
- 显示内容类型和复制时间。
- 每张卡片右上角显示来源 App 图标。

内容区：

- 文字显示前几行，超出截断。
- 图片显示卡片专用缩略图，保持比例，不直接读取原图参与卡片渲染。
- 链接显示标题或 URL。
- 颜色卡片标题栏和右上角图标仍使用来源 App 的主色和图标，内容区显示真实颜色值。
- 颜色卡片内容区文字颜色根据亮度自动切换黑色或白色。
- 底部显示字符数、图片尺寸或链接信息。

## 5. 预览层

- 从当前卡片上方弹出。
- 带小三角指向当前卡片。
- 保持轻量浮层感。
- 图片预览保持原始比例。
- 文本预览长内容可滚动。
- 颜色预览显示真实色块、HEX 和 RGB。
- 预览层不能遮挡系统菜单栏。
- 预览层最大尺寸应根据屏幕自动适配。
- `Command + 1-9` 序号提示使用非常短的淡入淡出和轻微缩放过渡，卡片图片和 App 图标必须使用内存缓存，避免按键时重新读图。
- 长文本预览使用原生文本视图渲染，避免 SwiftUI 长文本首屏渲染卡顿。

## 6. 右键菜单

菜单风格使用 macOS 原生或接近原生样式。

第一版菜单项：

- 粘贴
- 复制
- 置顶 / 取消置顶
- 预览
- 删除

删除操作使用危险色或系统危险操作样式。

## 7. 交互状态

必须有清晰状态：

- 默认
- 悬停
- 选中
- 置顶
- 暂停记录
- 搜索中
- 无结果
- 权限未开启

## 8. 可读性

- 标题栏文字颜色必须根据背景自动切换。
- 卡片内容不能溢出。
- 长文本必须截断或滚动。
- 图片缩略图不能拉伸变形，卡片中使用 `scaledToFit`。
- 所有按钮都要有明确 hover 或选中反馈。
- 设置页同一区域按钮超过一行时必须按用途分组，并使用分割线降低视觉拥挤。
- 设置页长按钮文字必须完整显示，不能被系统按钮压缩截断。
- 设置窗口默认宽度必须能完整容纳主要设置项，不允许出现左侧内容裁切。
- 设置页使用左侧分类导航、右侧内容区结构，避免所有设置项在一个长页面里堆叠。
