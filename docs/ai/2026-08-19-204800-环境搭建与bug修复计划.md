### 4.2 Bug 1：搜索时输入/删除字符卡顿

- **现象**：搜索框输入/删除字符时，**有结果**则非常卡；**无结果**则不卡。
- **根因（已用 codegraph + 读码确认）**：
  1. `HistoryWindowView.swift:826` 的 `historyRail` 里用 `ForEach(renderedWindowItems)` 渲染卡片，**外层是普通 `ScrollView(.horizontal)`，没有 `LazyHStack`/`LazyHGrid`**。所有匹配卡片全量渲染（非懒加载）。
  2. `HistoryWindowView.swift:682` `.onChange(of: searchUIState.text)` 每次输入字符都触发，导致整个 8353 行 View 的 `historyRail` 重算，所有卡片 body 重新求值。
  3. 无结果时 `renderedWindowItems` 为空 → ForEach 没东西渲染 → 不卡；有结果时卡片越多越卡。这完全解释了"有结果卡、无结果不卡"的现象。
  4. 搜索调度层（`HistorySearchCoordinator`）其实设计良好：已有 `debounceNanoseconds` 节流、`Task.detached` 后台过滤、generation 取消。**问题不在搜索逻辑，在 View 渲染层**。
- **方向**：
  - 把 `ForEach` + `ScrollView` 换成 `LazyHStack`（或 `LazyHGrid`）+ `ScrollView`，只渲染可见卡片。
  - 拆分 `HistoryWindowView.swift`（8353行）为子 View，缩小重算范围。
  - 搜索文本变化时，避免触发非必要区域重算（用独立 ObservableObject 隔离搜索状态）。

### 4.3 Bug 2：主窗口弹出/收起动画不流畅

- **现象**：向上弹出和向下收起流畅度不佳。
- **根因（已读码确认）**：`HistoryWindowController.swift:879 animateHistoryContentLayerTranslation` 用 `CABasicAnimation` 做 layer translation：
  - 第 901 行 `timingFunction = .linear` —— 线性曲线看起来生硬，弹出/收起应该用 ease-in-out 或 spring。
  - 动画期间 `setHistoryContentRasterization(true)`（第 863-868 行）开启栅格化，可能影响清晰度但提升性能；需确认 rasterizationScale 是否匹配。
  - 动画 completion 用 `Task.sleep` 等待时长（第 904-918 行），非 CAAnimation 的 completion block，时序可能有偏差。
- **方向**：
  - 把 timing function 从 `.linear` 改为 `.easeInEaseOut` 或自定义 spring。
  - 用 `CAAnimationDelegate` 的 `animationDidStop` 替代 `Task.sleep` 做完成回调，时序更准。
  - 检查 rasterizationScale = window.backingScaleFactor。
