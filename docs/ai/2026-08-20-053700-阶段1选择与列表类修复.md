## Issue 1：置顶时打开主窗口默认选中非置顶卡

### 问题现象
有置顶卡时，打开主窗口默认聚焦到非置顶的第一张卡，而非置顶卡。

### 根因
`latestPresentationCandidate`（HistoryWindowView.swift:3903）和 `primeLatestPresentationGuard`（HistoryWindowFocusState.swift:18）在新捕获项路径显式跳过置顶卡：`sourceItems.first { !$0.isPinned } ?? sourceItems.first`。因热键打开常伴随新捕获，此路径被触发，导致聚焦非置顶卡。

### 改动点
- `HistoryWindowView.swift:3908`：`sourceItems.first { !$0.isPinned } ?? sourceItems.first` → `sourceItems.first`（排序已置顶在前，无置顶时自然取最新非置顶）
- `HistoryWindowFocusState.swift:19`：`sourceItems.first { !$0.isPinned } ?? sourceItems.first` → `sourceItems.first`
- 决策：两路径（默认打开 + 新捕获）都优先选第一张置顶卡；无置顶才选最新非置顶

### 验证
`swift build` + `swift test` 通过

### 影响范围
窗口打开时的初始选中卡逻辑

## Issue 11：切换到某分组后，分组内卡片被移除后不立刻消失

### 问题现象
在某分组视图下，把卡片移出该分组后，卡片仍显示在列表里不立刻消失。

### 根因调查
- store 层：`removeItemFromGroup`（ClipboardHistoryStore.swift:1188）修改 `items[index].groupID = nil`，`@Published items` 的 willSet 正确触发通知。已写测试 `storeRemoveItemFromGroupUpdatesInMemoryItemsAndNotifies` 验证通过——store 层通知链路正确。
- view 层：`onChange(of: store.items)` → `schedulePreviewItemsRebuild`（async Task）→ 重建 allItems → `scheduleSearchUpdate` 重算筛选。链路完整但**异步**，重建 Task 完成前 UI 仍显示旧 `filteredItems`，导致"不立刻消失"。
- `HistoryPreviewItem.groupID` 是 `let`（不可变），无法原地改。

### 改动点
1. `HistoryWindowPreviewItemsState.swift`：新增 `mutating func syncItemGroupMutation(_ item: ClipboardItem)`——同步用 `HistoryPreviewItem(item:)` 重建并替换 allItems 里同 id 项，清 previewItemCache 该项，从 filteredItems/filteredItemIDs 移除该项（强制搜索重算）。
2. `HistoryWindowView.swift`：新增 `func applyItemGroupMutationFromStore(_ id:)`——从 store 取最新 ClipboardItem，调 `previewItemsState.syncItemGroupMutation`。
3. `Commands/HistoryCommandsContainer.swift:274`：`removeItemFromGroup` 命令在 `store.removeItemFromGroup` 后，立即调 `applyItemGroupMutationFromStore` + `scheduleSearchUpdate(immediate: true, debounceNanoseconds: 0)` 同步刷新，不依赖 async 重建。
4. 可见性：`applyItemGroupMutationFromStore`、`scheduleSearchUpdate`（两个重载）由 `private` 改 `internal`，供跨文件 Commands extension 调用。

### 验证
- `swift build` 通过
- 新增测试 `previewItemsStateSyncItemGroupMutationUpdatesAllItemsAndClearsFilteredEntry` 验证同步刷新逻辑正确
- `swift test` 相关 11 个测试全过

### 影响范围
移出分组命令的 UI 刷新时序；`HistoryWindowPreviewItemsState` 新增公开方法；两个 view 方法的可见性
