## 目标

修复选择搜索筛选条件后 token 不可见，以及搜索结果从第 21 张卡片开始无法预览、复制、编辑或打开的问题。

## 问题现象

1. 选择类型、来源 App、日期或分组筛选后，搜索框没有显示已选择的 token。
2. 搜索结果首屏虚拟窗口为 20 张卡片；继续浏览时，第 21 张及后续卡片的预览和各类菜单命令失效。

## 根因

1. 搜索输入框依赖隐藏视图异步测量 token 宽度；首次筛选时输入框仍占用几乎全部可用宽度，且 token 的滚动请求早于新布局完成，导致 token 被推出或留在可视区域外。
2. SQLite 搜索结果在协调器中只保留了 `HistoryPreviewItem`，丢失了完整 `ClipboardItem`。命令层仍通过内存中的 `ClipboardHistoryStore.items` 按 ID 查找实体；不在当前内存页中的后续搜索结果因此统一查找失败。
3. 初始搜索按 50 条读取，但又按 20 张渲染窗口截断结果，分页偏移却已经前进 50，导致第 21 至 50 条结果被跳过。

## 改动点

- token 存在时由 `SearchFieldLayoutPolicy` 确定性地为 token 保留一半轨道宽度，不再依赖隐藏视图异步测量；token 变化后的滚动延迟到下一布局周期执行。
- `HistorySearchFilterResult` 保留当前结果对应的完整 `ClipboardItem` 映射，并在后续分页中合并该映射。
- 卡片命令统一通过搜索结果实体解析；预览、打开和复制等只读操作直接使用结果实体，需要修改存储状态的命令才把已持久化实体接入内存 store，再复用现有逻辑。
- 初始搜索最多保留完整的 50 条数据库页，20 只作为渲染窗口目标，不再作为结果截断上限。
- 删除搜索结果时取消正在执行的旧分页任务，防止旧快照把已删除卡片重新加入列表。
- 键盘选择 token 时滚动到选中项；从最后一个 token 右移时滚回文本输入框。
- 补充 token 布局、第 21 张卡片可操作性和搜索实体状态回归测试。

## 验证

- 定向回归测试通过：4 项。
- `swift build -c release` 通过。
- `swift test --no-parallel`：591 项全部通过。
- 将搜索输入提交测试从固定 80ms 等待改为最长 2 秒的条件等待，消除全量并发测试下的调度波动。

## 影响范围

- 搜索框 token 布局。
- 搜索结果分页及完整实体生命周期。
- 搜索结果卡片的预览、复制、粘贴、编辑、链接/图片/文件打开、Finder 显示、置顶、分组和删除。
- 不改变 SQLite 搜索条件、普通历史分页或持久化格式。

## 约束对齐

- 修复集中在现有 Search、HistoryWindow、Commands 和 Storage 边界，没有新增跨模块隐式依赖。
- 使用共享实体解析入口，避免各命令单独实现第 21 张后的兼容逻辑。
