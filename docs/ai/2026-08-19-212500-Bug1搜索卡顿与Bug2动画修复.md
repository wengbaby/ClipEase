## 一、目标

修复两个 bug：
1. **Bug1**：搜索框输入/删除字符时，有结果则非常卡，无结果则不卡。
2. **Bug2**：主窗口向上弹出/向下收起动画不流畅。

## 二、Bug1 修复

### 2.1 根因（深入读码确认）

`HistoryWindowView.swift` 搜索结果应用链路：
- 第 687 行 `onChange(of: searchUIState.text)`：每次输入字符触发搜索调度，原 debounce 160ms（非 IME）。
- 第 5056-5060 行 `onResult`：搜索结果回来后，当 `shouldAnimateResults` 为 true 时启用 0.16s transition 动画。
- `shouldAnimateResults` 由 `shouldAnimateHistoryRailChange` 决定，阈值 `largeHistoryAnimationThreshold = 2000`——即结果数 <= 2000 时**总是启用动画**。
- `historyRail` 的 `ForEach(renderedWindowItems)` 上有 `.transition(.scale+.opacity)`（第 828-833 行），动画期间可见的 ~20 张卡片做 scale+opacity transition + offset 重算。
- 连续快速输入字符时，每个字符触发一次"搜索→结果应用→transition 动画"循环，动画叠加导致卡顿。
- 无结果时 `filteredItems` 为空，ForEach 无卡片渲染，整套重算跳过 → 不卡。

**注意**：`renderedWindowItems` 已有视口裁剪（`RenderWindowCoordinator`，`historyRailRenderedItemLimit = 20`），`HistoryCardView` 已用 `.equatable()`。卡顿主因不是"全量渲染"，而是**搜索结果变化时 transition 动画 + offset 重算在连续输入时叠加**。

### 2.2 改动点

文件：`Sources/ClipEase/Features/HistoryWindow/HistoryWindowView.swift`

1. 新增 `@State private var isSearchTextDrivenUpdate = false`（第 38 行）：标记本次搜索是否由文本变化触发。
2. `onChange(of: searchUIState.text)`（第 688 行）：设 `isSearchTextDrivenUpdate = true`；debounce 从 160ms 降到 100ms（英文输入响应更快；IME 组字仍 300ms 不变）。
3. 搜索结果应用（第 5056 行）：若 `isSearchTextDrivenUpdate` 为 true 则 `disablesAnimations = true`（禁用 transition 动画），应用后重置标记。

```swift
// 改动后
let isTextDriven = isSearchTextDrivenUpdate
let shouldAnimateResults = !isTextDriven && inputState.isWindowPresentedSnapshot && shouldAnimateHistoryRailChange(...)
if shouldAnimateResults {
    transaction.animation = .easeOut(duration: ...)
} else {
    transaction.disablesAnimations = true
}
if isTextDriven {
    isSearchTextDrivenUpdate = false
}
```

### 2.3 效果

- 连续输入字符时，搜索结果更新不再触发 transition 动画，避免动画叠加卡顿。
- 搜索框失去焦点/停顿后的搜索（非文本驱动，如 filter/分组变化）仍保留动画。
- debounce 100ms 让响应更快。

## 三、Bug2 修复

### 3.1 根因

`HistoryWindowController.swift` 动画：
- `panelAnimationDuration = 0.14`（140ms，偏短）。
- `CABasicAnimation`（第 901 行）和 `NSAnimationContext`（第 380、492 行）的 `timingFunction` 都是 `.linear`（匀速，弹出/收起显得突兀）。
- layer animation 的完成回调用 `Task.sleep(duration)`（第 904-918 行），sleep 时长 ≠ 实际动画时长，系统负载下时序偏差。

### 3.2 改动点（grill 共识 10A：统一参数和回调，两套动画并存不合并）

文件：`Sources/ClipEase/Features/HistoryWindow/HistoryWindowController.swift`

1. `panelAnimationDuration`：0.14 → 0.22（第 52 行）。
2. `CABasicAnimation.timingFunction`：`.linear` → `.easeInEaseOut`（第 901 行）。
3. `NSAnimationContext.timingFunction`：两处 `.linear` → `.easeInEaseOut`（第 380 行 show + 第 492 行 close）。
4. layer animation 完成回调：`Task.sleep(duration)` → `CATransaction.setCompletionBlock`（第 892-918 行）。completion block 由 Core Animation 在动画真正结束时触发，时序精准。

```swift
// 改动后
CATransaction.begin()
CATransaction.setCompletionBlock {
    Task { @MainActor [weak self, weak panel] in
        guard let self, let panel,
              self.contentLayerAnimationGeneration == generation else { return }
        panel.contentView?.layer?.removeAnimation(forKey: key)
        completion()
    }
}
layer.add(animation, forKey: key)
CATransaction.commit()
```

### 3.3 效果

- 弹出/收起用 easeInEaseOut 曲线 + 220ms 时长，观感平滑不突兀。
- 动画完成回调时序精准（Core Animation 驱动，非 sleep）。
- 两套动画体系（CABasicAnimation layer translation + NSAnimationContext frame）并存保留，各自参数统一。

## 四、影响范围
